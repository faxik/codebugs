## 2. Числа, которые надо исправить

### И-1 (несущее). «git ошибается в 0.21%» — ошибается не git, а мерилка

`revblame_measure.py:173` читает `git show {head}:{f}`, где `f` — **записанный в карточке**
путь, и сверяет с ним номер строки, который blame выдал. При этом **П3 самого документа**
пишет: «Записи `filename` несут путь в последней ревизии — им и ловится переезд». Мерилка
эту запись не читает.

Единственное «расхождение» — CB-3055. Проверено исполнением:

```
blame --reverse -C : src/autosorter/watcher/service.py:503 -> ignore_rules.py:168
git show HEAD:src/autosorter/watcher/ignore_rules.py | awk 'NR==168'
  ->            for root_str, loader in self._asignore_loaders.items():
```

Это **побайтно** тот текст, который blame и обещал. Код вынесен в другой файл — ровно тот
случай `moved_file`, ради которого канал A и выбран.

Исправленной сверкой (путь берётся из `filename`) на всех конфигурациях флагов:

| | codebugs | autosorter |
|---|---|---|
| строк дожило | 58 | 479 |
| совпало **побайтно** | 58 (100.00%) | **479 (100.00%)** |
| разошлось | 0 | **0** |

**Что править:** П4 («и он ОШИБАЕТСЯ в 0.21% случаев»), строку §1б «разошёлся 1 (0.21%)»,
строку «что решает», Р2 п.2 («П4: 0.21% координат уверенно неверны»), §8 п.3 («git ошибается
в 0.21% случаев»), REVBLAME §5 целиком, строку приложения «1 из 479 координат blame уверенно
неверна».

**Что это делает с решением хранить текст.** Оно НЕ отменяется — текст ратифицирован
владельцем и нужен каналу B, — но **обоснование «проверять git, потому что он врёт»
рассыпается**: измеренная частота ошибки git = 0/537 строк на двух корпусах. Сверка остаётся
защитой от переписанной истории, испорченного `meta` и от резолвера, который забыл прочитать
`filename`. Это надо сказать этими словами, а не цифрой 0.21%.

**Побочно И-1 усиливает дизайн:** статус `moved_file` получает **реальный** случай на живой
истории (CB-3055), а не только синтетический `/tmp/bt7rn`. Соответственно REVBLAME §6
(«ноль… ни при одном флаге», «частота нулевая») и §1б-строка про `-C` против `-M -C` неверны
и должны быть переписаны: на живом переезде оба флага ведут себя одинаково, `-C -C` находит
второй случай.

### И-2 (несущее). Годность канала B посчитана по предикату захвата, который v5 удалила

Р3 и §7.1 говорят однозначно: текст берётся **только** через `git show <commit>:<path>`,
чтение с диска убрано, отказы `no_commit` / `commit_unreachable` / `path_absent_at_commit`
закрыты токенами. Значит **у карточки без разрешимого коммита якоря нет вообще — ни для A,
ни для B**: канал B — это способ РАЗРЕШЕНИЯ уже захваченного текста, а не второй способ
захвата.

Строка «годна каналу B (файл читаем сейчас) 47 / 654» меряет предикат захвата **v4**
(прочитать рабочее дерево). Под семантикой v5 B ⊆ A-захват, и таблица должна читаться так:

| | codebugs | autosorter |
|---|---|---|
| грамматика (потолок) | 47 (36.4%) | 685 (20.8%) |
| захват возможен (v5: коммит + путь в нём + пролёт) | **37 (28.7%)** | **314 (9.5%)** |
| годна хотя бы одному каналу | **37 (28.7%)** | **314 (9.5%)** |

Из 656 «годных» 342 (52%) — карточки, которым v5 не может захватить текст ни одним способом.
Дополнительно: у 36 из 654 «B-годных» пролёт лежит **за пределами текущего файла** (654 → 618).

Это же чинит §10 п.2 («для этой популяции существует канал B») — без диска для популяции
«нет git» текста тоже неоткуда взять.

## 3. Экстраполяция §8: **НЕЗАКОННА** (autosorter), **наполовину законна** (codebugs)

Документ говорит владельцу: «**локацию получат ~21–29% карточек codebugs и ~15% autosorter**».
Это единственное число, по которому принимается решение.

### Откуда взялось

- codebugs `~21–29%`: 27/129 = 20.9% (измеренный пол) … 37/129 = 28.7% (потолок, если все 10
  «только-B-годных» разрешатся). Арифметика сходится.
- autosorter `~15%`: **656 × 74.8% / 3300 = 14.9%**. Другого разложения, дающего 15%, нет.

### Почему autosorter незаконна — два дефекта, и они умножаются

1. **74.8% — доля со смещённой выборки 250** (И-3). На переписи той же популяции — 67.0%.
2. **Она применена к 656**, из которых **342 (52%) не годны каналу A**. Канал A даёт 70.8 из
   этих 74.8 п.п.; на 342 карточках он неприменим ПО ПОСТРОЕНИЮ. А по И-2 на них неприменим и
   канал B, потому что захватывать текст нечем.

Это ровно тот класс, который документ сам заносит в реестр уроков: **доля, снятая на популяции
P, перенесена на Q ⊋ P, где механизм, эту долю производящий, не работает.** Тот же дефект, что
«доля читаемых файлов выдавалась за долю заякориваемых» — третий раз, новой дверью.

### Что даёт замер

| сценарий | autosorter | codebugs |
|---|---|---|
| **по дизайну v5** (захват через `git show`; перепись, оба канала) | **209 / 3300 = 6.3%** | **27 / 129 = 20.9%** |
| если вернуть захват с диска для 342 и перенести на них долю B (46.2%) | (209 + 158)/3300 = **11.1%** | 27–37/129 = 21–29% |
| абсолютный потолок (разрешится всё «годное») | 656/3300 = 19.9% | 47/129 = 36.4% |
| **в документе** | **~15%** | ~21–29% |

`~15%` **в 2.4 раза выше** того, что поддерживает собственный дизайн v5, и выше даже самого
щедрого сценария с возвращённым диском. Оно требует, чтобы 342 неизмеренные карточки
разрешались на ~74.8% — выше, чем канал B показал где-либо (46.2% и 27.0%).

codebugs: нижний конец `~21%` — **измеренный пол, верен**. Верхний `29%` держится на тех же
двух допущениях (10 «только-B» карточек разрешаются на 100% **и** канал захвата, которого в
v5 нет). Диапазон вдобавок нигде не назван «пол…потолок», и читается как доверительный.

### Формулировка, которую замер поддерживает
