## §1. Замысел

Владелец просил, чтобы документация показывала пользу инструмента и **не обещала больше, чем держит
код**. Юнит Т-104 сделал большую часть работы и был принят с оговоркой: две приёмки нашли семь мест,
где обещание всё ещё шире факта, и — что важнее — **два из них юнит внёс сам**, причём одно ровно в
том предложении, которое добавлялось ради честности.

Вред здесь не «текст неаккуратен». Вред в том, что **читатель принимает решение по написанному**:
запускает сервер с режимом, который тот отвергает; ищет одну строку диагностики там, где их две;
верит, что карточка переживёт правку файла, тогда как это верно для одной карточки из четырнадцати.

**Чего юнит НЕ делает.** Не переписывает README заново — Т-104 его перестроил, и перестройка
принята. Не трогает грамматику захвата якорей. Не заводит новых гейтов сверх названных ниже.

## §3. Форма выбрана уровнем (2)

Правило, общее для всех семи: **где утверждение можно закрыть ПО ПОСТРОЕНИЮ, закрывай построением;
где нельзя — сужай обещание и говори это вслух.** Прозой не чинится ничего, что можно сравнить
множествами.

### 3.1. Части (1), (4), (6) — прозаические, чинятся текстом, проверяются прогоном

Три предложения. Для (1) — назвать оба канала раздельно: флаг есть утверждение об этом вызове и
создаёт в названном каталоге; ambient-переменная перенаправляет только чтения и предупреждает. Для
(6) — либо назвать верное число, либо, что лучше, **сказать без числа**: «пишет в поток ошибок
диагностику». Для (4) — либо показать поле, либо поставить многоточие.

### 3.2. Часть (5) — ЗАКРЫВАЕТСЯ ПО ПОСТРОЕНИЮ, и это главное решение брифа

Текст поправить надо, но **одного текста мало**: расхождение возникло потому, что два списка
режимов живут врозь и никто их не сравнивает. Гейт уже умеет сравнивать множество модулей README с
разрешённым списком `--mode` у CLI. **Добавь второе сравнение — с `SERVER_NAMES` сервера** — и
пусть гейт утверждает то, что есть на самом деле: списки различаются, и различие ровно такое-то.

Это дёшево (гейт уже читает один список, читать второй — та же операция) и закрывает класс: в
следующий раз, когда режим появится у одной поверхности и не появится у другой, покраснеет тест, а
не пользователь.

### 3.3. Часть (2) — расширять на СПОСОБНОСТЬ, а не перечислять написания

Забор есть забор при любом отступе и при любой длине не меньше трёх; первым токеном команды может
стоять флаг, и глагол тогда дальше. Оба — свойства грамматики, а не список написаний. **Соблазн,
который здесь запрещён:** дописать в разборщик пару частных случаев, чтобы четыре формы приёмщика
позеленели. Это ровно тот дефект, который чинится, и направление платит за него чаще всего.

Если какая-то форма не берётся расширением на способность — **объяви её в докстринге поимённо**, и
это законный исход. Необъявленный промах дороже объявленного.

### 3.4. Часть (7) — счёт СНЯТЬ, а обещание докстринга СУЗИТЬ

Счёт из прозы убрать, а не пересчитать. **И отдельно: докстринг гейта утверждает, что README не
несёт счетов в прозе, — это утверждение снять.** Гейт на счета в английской прозе был бы машиной
ложных срабатываний (в тексте полно законных числительных), поэтому здесь правильный ход —
перестать обещать, а не начать проверять. Скажи это в докстринге прямо: почему не гейтится.

### 3.5. Часть (3) — обещание становится УСЛОВНЫМ, не снимается и не остаётся безусловным

`INSTRUCTIONS` в `src/codebugs/server.py` — поверхность, которую видит каждый клиент MCP. Сегодня:
«место в коде привязывается автоматически при заведении, поэтому карточка переживает последующие
правки файла», без единого условия.

- **Снять целиком нельзя:** механизм есть, он работает и он полезен.
- **Оставить как есть нельзя:** верно для одной карточки из четырнадцати.
- **Надо: назвать условие** — привязка происходит, когда в описании названо место в коде, которое
  захват умеет разобрать; и назвать, чем проверить (`anchor_resolve`), потому что читатель должен
  уметь отличить одно от другого сам.

**Числа в этот текст не ставить.** Доля меняется с каждой карточкой; условие — не меняется.

## Эскалации

Заполнено исполнителем Т-107 по итогам работы. Слот **не пустой**: три расхождения с числами
брифа, все три — поправки к ДАННЫМ, ни одно не потребовало обходить замысел. Ни одна из пяти
предпосылок §4 не провалилась по сути; расходятся сопровождающие их числа, и это важно, потому
что два из трёх чисел брифа описывают ровно тот механизм, который юнит закрывает по построению.

**Э-1. Состав множеств режимов в §2(5) описан неверно — обе половины (повод «а», частичный).**
Бриф говорит: «у CLI и у сервера по 14, но **только у CLI `usage`, только у сервера `all`**».
Измерено мной самостоятельно, чтением обоих источников и запуском обеих поверхностей: у CLI
**15** значений (`cli.py:288`, литеральный список в `choices=`), у сервера **14** (ключи
`SERVER_NAMES`, `server.py:557`). `all` есть **у обеих** поверхностей. Симметрическая разность —
ровно `{usage}`, один элемент, а не два. Существо предпосылки П2 при этом воспроизвелось
полностью: `python -m codebugs.server --mode usage` печатает `argument --mode: invalid choice:
'usage'` и завершается кодом **2**, сервер не стартует; множества действительно различаются по
составу. Замысел §3.2 от этой поправки не меняется — сравнение множеств нужно ровно затем, зачем
названо, — но текст README я написал по измерению, а не по брифу: он говорит про `usage` и не
говорит ничего про `all`. Стоит отметить, что докстринг гейта, написанный юнитом Т-104, **уже
нёс правильные числа** (15 и 14); ошибочен был именно бриф, и это тот случай, когда перепроверка
предпосылки окупилась.

**Э-2. Из четырёх форм приёмщика в §2(2) одна у меня не воспроизвелась — «забор из четырёх
кавычек» (повод «а», частичный).** Старый разборщик переключал признак «внутри забора» по
`line.startswith("```")`, и строка ```` ```` ```` этому условию **удовлетворяет**. Симметричный
забор из четырёх кавычек поэтому читался старым гейтом корректно: форма `V06-four` в моём корпусе
**поймана и ДО правки**. Что действительно ломало старый разборщик — соседняя форма, которую бриф
не называет: строка из трёх кавычек **внутри** блока из четырёх. По CommonMark она блок не
закрывает, старый код закрывал, признак инвертировался, и **все последующие примеры документа**
становились невидимыми — ослепление не одного блока, а всего файла ниже. Это форма `V11-desync`,
до правки пропущена, после — поймана. Остальные три формы приёмщика (отступ пробелом, отступ
табуляцией, неопознанный флаг первым токеном) воспроизвелись как описано.

**Э-3. Знаменатель П5 сместился на единицу (повод «а», несущественно).** Бриф: 22 карточки с
рабочим якорем из 232, строгим счётом 16 — то есть 6,9 %. Измерено мной чтением боевого трекера:
карточек всего **233** (за смену завелась ещё одна), с захваченным якорем — **22**, указывают на
живой код (исходы `moved`/`current`/`moved_file`) — **16**, то есть **6,87 %**. Оба несущих числа
совпали точно; разошёлся только знаменатель, и ровно на ту единицу, которую объясняет течение
времени. Вывод брифа — «верно для одной карточки из четырнадцати» — держится (16/233 ≈ 1 из 14,6).

**Поводы, которые НЕ наступили, разобраны поимённо, как требует §7.**

- **(б) `loc.py` не понадобился.** Формулировка `INSTRUCTIONS` чинится словами: обещание стало
  условным («когда наблюдение назвало место в коде»), и ни грамматика захвата, ни один файл
  `src/codebugs/loc.py` не тронуты. Проверено `git diff --stat`: файла в диффе нет.
- **(в) Нового источника истины не потребовалось.** Гейт читает второй список **там, где тот уже
  живёт** — ключи `SERVER_NAMES` разбираются из `server.py` через AST, ровно тем же способом и с
  той же политикой «непонятная форма — отказ», каким гейт уже читал список CLI. Ни один список
  никуда не вынесен, архитектурного решения не принято.
- **(г) Форм, не закрываемых расширением на способность, четыре, и все четыре объявлены поимённо**
  в докстринге гейта: пример в отбитом четырьмя пробелами блоке без забора; вызов другим
  написанием программы (`python -m codebugs.cli`, `uv run codebugs`); пример внутри цитаты (`>`);
  таблица инструментов с другими именами столбцов — последняя молчит только начиная со второй
  таблицы, при полном отсутствии таблиц гейт отказывает. Каждая измерена прогоном, а не
  предположена: они и есть ровно те 4 из 31, что мой корпус не ловит после правки.
- **(д) Существующих утверждений тестов я не ослаблял.** Единственная правка в чужом тесте —
  **строка в объявленной таблице исключений** `_DECLARED_NON_TOOL_TOKENS`
  (`tests/test_server.py`), созданной ровно для этого случая: новый текст `INSTRUCTIONS` называет
  в обратных кавычках `meta.line` / `meta.lines`, а это **входные ключи наблюдения**, не имена
  инструментов. Строка снабжена причиной, и таблица самоудаляющаяся — исчезнет токен из текста,
  тест на устаревшие строки покраснеет. Ни одно утверждение не смягчено; расширены только
  проверки. Единственное изменённое существующее утверждение гейта — заголовок таблицы
  инструментов больше не сверяется побайтово, а узнаётся по **именам столбцов**; это ужесточение
  (форма `T02`–`T04` до правки проходила молча), и оно объяснено в докстринге.
- **(е) Голдены не двигались, файлы соседних направлений не тронуты.** `tests/golden/mcp_schema.json`
  не содержит поля `instructions` (проверено), поэтому правка текста инструкций его не смещает;
  `git status` подтверждает, что голден не изменён.
