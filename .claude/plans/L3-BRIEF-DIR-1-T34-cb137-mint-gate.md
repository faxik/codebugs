## §1. Замысел

`tools/cascade-mint.sh` (Т-29) закрывает минт, **сделанный скриптом**: под `flock` вычисляет
`max+1` по всему реестру, дописывает и коммитит одной операцией, автор номера не набирает. Ничто не
мешает следующему автору набрать номер руками и закоммитить `.claude/plans/CASCADE-IDS.md`
обычным `git commit`. **Именно так случились все три коллизии**, и третья — при формально
соблюдённом правиле: защищено было ЧТЕНИЕ хвоста, а не ВЫЧИСЛЕНИЕ номера.

Это доктрина этого репозитория, применённая к себе: **проза не энфорсит прозу; скрипт — удобство,
пока нет отказа.** Инструмент без гейта — четвёртая коллизия достижима рукой.

## §2. Форма — принята уровнем (2), с ОДНОЙ правкой буквы карты

**Правило живёт внутри УЖЕ СУЩЕСТВУЮЩЕГО `tools/pre-commit-hook.sh`, в ветке `branch == main`,
после того как аллоwлист путей уже пропустил коммит.** Не новый файл хука — и это не вкусовщина:
`_guard_enforcement_armed` гейтит на наличие ИСТОРИИ у путей `tools/pre-commit-hook.sh` и
`tools/pre-merge-commit-hook.sh`, поэтому четвёртый хук упёрся бы в bootstrap-стену, которую этот
репозиторий проходил уже трижды (CLAUDE.md описывает её для CB-57 подробно). Внутри существующего
файла стены нет, а вооружённый клон получает правило сразу: `install-hooks.sh` ставит СИМЛИНК на
файл в рабочем дереве.

**ПРАВКА БУКВЫ КАРТЫ, смысл сохранён — прочти внимательно, это ядро юнита.** Карта говорит:
«правило обязано читать ДОБАВЛЕННЫЕ СТРОКИ диффа, а не файл целиком, иначе оно не отличит минт от
правки». Замысел («отличить минт от правки») принимаю целиком; **механизм «добавленные строки» его
не обслуживает и даёт ложный отказ.** Причина конкретна и уже случалась в этом репозитории: при
переименовании брифа (`git mv`, реальный случай коллизии №2) строка реестра правится, и в диффе
это **добавленная строка, несущая УЖЕ ПОТРАЧЕННЫЙ ID**. Предикат по добавленным строкам объявит
это минтом израсходованного номера и откажет правке, которая минтом не является.

**Правильный механизм — множество ПОЯВИВШИХСЯ ID:**
`new = ids(staged blob) \ ids(HEAD blob)`, по каждому семейству префиксов отдельно.

- `new` пусто → это правка, пропускаем.
- `|new| == 1` → минт; ID обязан быть равен `max+1` по **всем остальным** ID своего семейства в
  staged-версии файла.
- `|new| > 1` → отказ, называя скрипт: инструмент минтит по одному.

Это отличает минт от правки ТОЧНО, а не по форме диффа.

## §3. Обязательные части

1. **Гейт в `tools/pre-commit-hook.sh`**, по §2. Срабатывает только когда staged-множество
   содержит `.claude/plans/CASCADE-IDS.md`, только на `main`.
2. **Предикат нумерации не расходится с инструментом.** Карта требует этого прямо. Механизм —
   твой, с обоснованием; требуемое СВОЙСТВО одно: **правка одной стороны без правки другой обязана
   краснить сьют, и это доказывается мутантом, а не заявляется.** Два кандидата, оба легитимны:
   (а) байт-идентичный разделяемый блок между маркерами `# ---8<---`, как это уже сделано для
   merge-gate предиката между двумя хуками (CB-57), плюс тест, сравнивающий блоки **дословно**
   (не грепом по подстроке — CLAUDE.md записывает, почему греп оказался недостаточен);
   (б) поведенческий тест эквивалентности: оба вычислителя прогоняются по одному корпусу реестров
   и обязаны дать один ответ. **Хук НЕ МОЖЕТ ни `source`-ить `tools/`, ни звать
   `cascade-mint.sh`** — он работает из `.git/hooks/` симлинком и обязан работать, когда `tools/`
   в дереве нет.
3. **Сообщение отказа называет `tools/cascade-mint.sh`** (карта, п.3) — гейт без названного выхода
   стоит стеной. По образцу соседних отказов этого файла: что именно не так, чем это чинится,
   и что `git commit --no-verify` остаётся сознательным исключением.
4. **`CLAUDE.md`: строка в таблице «What is now mechanically enforced»** — правило, механизм,
   «refuses with: exit 1». Без переструктурирования таблицы и соседней прозы.

## §4. Ловушки — здесь их больше обычного, читай все

1. **Читать ИНДЕКС, а не рабочее дерево.** Staged-версия файла — `git show :<path>`; версия HEAD —
   `git show HEAD:<path>`. Если прочитать файл с диска, незастейдженная правка меняет вердикт, и
   гейт судит не то, что коммитится.
2. **Семейства префиксов раздельны, а `Т` имеет ДВА написания.** Реестр несёт `Т-` (КИРИЛЛИЧЕСКАЯ
   ТЭ, U+0422, два байта в UTF-8), `BT-` и `DIR-`. Инструмент СКАНИРУЕТ оба написания `Т`/`T`
   (латинская опечатка не должна стать невидимой для аллокатора) и ПИШЕТ кириллическое. `max+1`
   считается внутри семейства, а не по всему файлу. И `export LC_ALL=C` — инструмент пинует
   байтовую семантику именно чтобы вердикт не зависел от локали коммиттера; гейт обязан пиновать
   так же, иначе два определения одного правила разойдутся на первой же машине с другим `LANG`.
3. **Аннулированные строки — ПОТРАЧЕННЫЕ номера.** Реестр несёт строки «КОЛЛИЗИЯ №N … АННУЛИРОВАНА»
   и сами аннулированные строки. Инструмент считает `max+1` по КАЖДОЙ строке сознательно. Гейт,
   который «умнее» и пропускает аннулированные, разойдётся с инструментом на первом же переминте —
   это ровно то, о чём предупреждает п.2 карты.
4. **Ноль найденных ID — ОШИБКА, а не пустой аллокатор.** Инструмент отказывается в этом состоянии
   явно и объясняет почему. Гейт обязан вести себя так же: `grep` с кодом 0 / 1 / ≥2 — это ТРИ
   разных ответа, и только один из них значит «в реестре нет ID». Слияние ошибки с пустым
   результатом — форма, за которую этот репозиторий платил в bootstrap-гейте, в `MERGE_HEAD` и в
   `_guard_conflict_markers`.
5. **Файла нет в HEAD** (первое создание реестра) — все ID «новые». Отказывай fail-closed, назвав
   `--no-verify` как способ заявить намерение. Не изобретай «если файла не было, всё можно».
6. **Мердж-исключение выше по файлу гейт НАСЛЕДУЕТ.** `[[ -e "${git_dir}/MERGE_HEAD" ]] && exit 0`
   стоит до ветки `main` и пропускает весь staged-набор. Значит оператор, вошедший в состояние
   мерджа, обходит и твоё правило. **Это не дыра, которую ты открыл** — она уже описана в
   `CLAUDE.md` как цена мердж-исключения. **Назови её вслух в возврате как честный остаток**, не
   чини и не расширяй исключение.
7. **Собственный коммит инструмента обязан ПРОХОДИТЬ.** Гейт, отказывающий своему же скрипту, —
   гейт, которым нельзя пользоваться. Это обязательная ПОЛОЖИТЕЛЬНАЯ проба, прогнанная во
   временном репозитории (не в основном чекауте: скрипт коммитит на main).
8. **`--no-verify` остаётся** (карта, п.4): гейт против случайности, не против намерения, — как у
   всех остальных хуков этого репо.
9. **Мутационная проба в точку:** мутант — снять твой предикат (или сломать `max+1` на `max`);
   названный тест обязан покраснеть. `PYTHONDONTWRITEBYTECODE=1`, чистый `__pycache__`,
   `grep -c` подтверждает, что мутант применён.
10. **Не трогать `.python-version`, не запускать `uv sync` / `uv run --python`.**

## §9. ПРИЁМКА УРОВНЯ (3) — заполнено исполнителем на ветке `fix/t34-mint-gate`

**Правка буквы брифа, о которой держатель обязан узнать первым.** §2 предписывает
`new = ids(staged) \ ids(HEAD)` как множества. **Этот механизм не ловит коллизии №2 и №3 —
то есть ровно те, ради которых заведена карта.** В обеих номер, набранный рукой, УЖЕ БЫЛ в
реестре в момент коммита (соседнее направление приземлило его минутами раньше), поэтому
разность множеств пуста и гейт пропускает. Измерено на живом реестре до того, как этот абзац
был написан: рукописная строка `- Т-21 — …` рядом с существующей `Т-21` принята, rc=0.
Замысел §2 («отличить минт от правки, не отказывая правке строки») сохранён целиком; изменён
носитель:

- судится **АЛЛОКАЦИОННАЯ СТРОКА** — строка, ОТКРЫВАЮЩАЯСЯ id (`- Т-37 — …`), в отличие от
  заметок реестра, которые открываются словом (`- КОЛЛИЗИЯ №2 …`) и id лишь УПОМИНАЮТ;
- разность считается **МУЛЬТИМНОЖЕСТВОМ** (по кратности), поэтому вторая аллокационная строка
  на уже занятый номер видна;
- `max` берётся по **ВСЕМ** вхождениям семейства в блобе **HEAD** — аннулированные строки и
  упоминания включительно, потому что это ровно та популяция, которую читает инструмент
  (он отказывается работать на грязном реестре, значит читает байты HEAD).

Побочный выигрыш: упоминание свободного номера в заметке о коллизии остаётся законным —
множественный вариант отказал бы ему.

**Механизм §3.2 — (б), поведенческая эквивалентность, а не байт-идентичный блок.** Причина
названа: два читателя получают РАЗНЫЕ входы (инструмент — файл рабочего дерева, гейт — два
блоба индекса) и отвечают на РАЗНЫЕ вопросы (`max+1` против «это ли max+1»), а
«разделяемая реализация не разделяет решение, когда вызывающие подают разные входы» — это
поправка, которую уже пришлось внести в разделяемый merge-предикат CB-57. Поэтому согласие
пинуется там, где оно принимается — на ОТВЕТЕ:
`TestCascadeMintGate::test_the_gate_accepts_exactly_the_id_the_tool_hands_out` гоняет
НАСТОЯЩИЙ `tools/cascade-mint.sh --dry-run` и НАСТОЯЩИЙ хук по одному корпусу реестров и
требует, чтобы гейт принял ровно выданный инструментом id и отказал обоим соседям.
`tools/cascade-mint.sh` НЕ ПРАВЛЕН — файловый набор 3 правки из 4 разрешённых.

**Мутанты (по одному на сторону, `PYTHONDONTWRITEBYTECODE=1`, чистый `__pycache__`,
применение подтверждено `grep -c`):**

| мутант | сторона | сьют |
|---|---|---|
| `max+1` → `max` в гейте | гейт | 13 failed |
| семейство единиц теряет латинскую ветвь | гейт | 1 failed — `…tool_hands_out[a latin typo carries the maximum:Т]` |
| сканер теряет ЛЕВУЮ ГРАНИЦУ | гейт | 2 failed — `test_the_families_are_independent`, `…[a large BT id must not raise the unit counter:Т]` |
| `max` только по аллокационным строкам | гейт | 1 failed — `…[the maximum appears only inside guillemets:Т]` |
| правило вообще не вызвано | гейт | 15 failed |
| **`cascade-mint.sh` теряет латинскую ветвь** | **инструмент** | 1 failed — `…[a latin typo carries the maximum:Т]` |
| **`cascade-mint.sh` `max+1` → `max`** | **инструмент** | 10 failed |

Две последние строки — это и есть доказанное требуемое свойство §3.2: правка ОДНОЙ стороны
без правки другой краснит сьют.
