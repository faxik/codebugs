## 1. Задание

`loc.py` (следующий юнит) обязан привязывать захват якоря к **worktree-корню** и
разрешать путь внутри него. Сегодня оба умения приватны:

- `provenance._repo_root(cwd)` — worktree-корень, `realpath`, `None` если git не может.
- `provenance._resolve_candidate(root, file_path)` — разрешение пути в корне.

Правило модулей репозитория (CLAUDE.md): домен не тянет приватности другого домена.
Значит нужен ПУБЛИЧНЫЙ вход. Построй его.

**Предпосылки, добытые мной из кода (спот-чекни первым делом; расхождение = СТОП и доклад):**
- `provenance.py:59` `_repo_root(cwd)`, `:75` `_resolve_candidate(root, file_path)` — оба
  приватны, оба уже существуют и работают; изобретать заново НЕ надо, надо ЭКСПОНИРОВАТЬ.
- `_repo_root` идёт через `db.git_rev_parse("--show-toplevel", silent=True, cwd=cwd)`,
  который уже несёт кортеж исключений CB-79. Не заводи шестой рукописный `subprocess` —
  докстринг `_repo_root` прямо объясняет, почему их ровно пять.
- `provenance.head_sha(*, project_dir=None)` (`:252`) — образец сигнатуры публичной функции
  этого модуля с `project_dir`. Держись его формы.
- `_resolve_candidate` НАМЕРЕННО сохраняет финальный симлинк (см. его докстринг). Для
  классификации git-блоба это верно. **Не меняй его поведение** — если новому API нужна
  другая семантика, он её выражает СВОИМ параметром, а не правкой чужого контракта.

**Форма — гипотеза, преflight вправе предложить лучшую.** Мой набросок:
`provenance.worktree_root(*, project_dir: str | None = None) -> str | None` и
`provenance.resolve_in_worktree(root: str, file_path: str) -> str`.
Смысл, который держим: **захват якоря должен уметь спросить «какой у меня корень» и
«куда указывает этот путь» публично, без обращения к приватностям и без ambient cwd.**
Буква (имена, ровно два входа или один) — твоя.

**Явный НЕ-скоуп, и он важен.** v5 требовала от этого юнита ещё и структурный `new_path`
в вердикте `renamed`. **v6 это требование СНЯЛА** — переезд теперь отслеживает
`git blame --reverse` (запись `filename`), и парсер прозы не нужен. Не строй его.

## 2. Тесты

- Публичные функции покрываются напрямую: обычный чекаут; **linked worktree** (там
  `describe_root()` даёт корень main, а нужен корень ВЕТКИ — это ровно то, ради чего юнит);
  каталог без git → `None`, не исключение; несуществующий `project_dir`.
- **Мутационная проба обязательна и делается во ВРЕМЕННОМ worktree**
  (`git worktree add <tmp> <sha>` → проба → `git worktree remove --force`), НИКОГДА в
  рабочем дереве (инцидент Т-15).
- Ничего в существующем поведении `file_status`/`check_findings` не должно сдвинуться:
  докажи это формой диффа (экспонирование = обёртки), а не только зелёным прогоном.
