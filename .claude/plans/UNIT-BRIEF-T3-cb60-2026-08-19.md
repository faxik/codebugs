## prescription (HYPOTHESIS — расхождение с реальностью = стоп и доклад Т-3)

Объём — строго четыре пункта, ничего сверх:

1. **Тривиальная нормализация написания категории на пути записи наблюдения**
   (`add_finding` / `batch_add_findings`): casefold, дефис→подчёркивание, схлопывание
   whitespace (внутреннего — в один `_`? нет: whitespace схлопнуть и заменить на `_`
   только если так решит тест на твины из evidence; минимум — strip + внутренние
   пробелы → `_`), применяется ДО деривации fingerprint, так что хранится и хэшируется
   каноническое написание. Функция нормализации — публичная, в `types.py` или
   `findings.py` (решает исполнитель; types.py — zero-dependency, подходит).
2. **Near-hit подсказка канона**: предлагаемое (уже нормализованное) имя, близкое к
   существующей в БД категории, но не равное ей → `ValueError` с подсказкой
   канонического написания (существующего имени). Метрика близости — дёшево и
   объяснимо (например, расстояние Левенштейна ≤ порога на нормализованных именах или
   схожесть по триграммам); порог консервативный — false-refusal хуже пропуска,
   escape — флаг из п.3.
3. **Genuinely-new имя требует явного флага** (например `new_category: bool = False`
   на add/batch_add, MCP + CLI `--new-category`) **и подсчитывается** — минтинг
   становится видимым (минимально: стамп `meta` вида `category_minted: true`, чтобы
   `query(meta_key="category_minted")` давал счёт; новая таблица НЕ нужна). Без флага
   новое имя (не равное и не near-hit ни одной существующей категории) — отказ с
   перечислением ближайших существующих. Имя, уже существующее в БД (после
   нормализации равное существующему) — проходит без флага.
4. **НЕ трогать**: хранимые auto:v1 fingerprints (никакого пересчёта, никакого bump
   версии); CB-54 (наивный strip volatile meta) — известное ограничение, НЕ чинить;
   существующие строки НЕ переписывать (ретро-fold — CB-61, остаётся заблокированной);
   `import_findings` и restore-путь — НЕ наблюдение, гейт near-hit/флага на них НЕ
   распространяется (иначе restore бэкапа со старыми именами ломается); нормализацию
   на import тоже НЕ применять — import хранит как есть (verbatim контракт CB-51).

Известное и принятое следствие (НЕ дефект юнита): существующая строка со старым
написанием (`process-improvement`) не будет матчиться по fingerprint новым
нормализованным наблюдением — это ровно зазор CB-61 (ретро-fold), заблокированной до
приёмки этого юнита.

Сериализация с DIR-1 (CLM-14, CB-106, ветка fix/cb-106-codemerge-closeability):

  трогает уже хранимые категории/fingerprints (auto:v1 хранимые стабильны).
- Существующая категория (точное нормализованное совпадение) проходит без флага.
- Wire golden обновлён и `tests/` зелёные целиком из worktree; ruff check чист.
