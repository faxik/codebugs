## 1. Задание (гипотеза, не приказ — П-Б)

`codebugs add -l "10-20" --meta '{"lines": [10, 20]}'` сохраняет **только список из
`--meta`**; строка из `-l` не попадает никуда и вызов рапортует успех. Это класс CB-15
(«объявленный аргумент обязан дойти до назначения, либо вызов обязан упасть»).

**Предпосылки, добытые мной ИЗ КОДА (не из памяти о коде; К-7). Спот-чекни их первым
делом — если хоть одна не воспроизводится, СТОП и доклад, не исполнение:**

- `src/codebugs/findings.py`, функция `_cmd_add` внутри `register_cli`. Грепаемые якоря
  (номера строк не цитирую — К-5 урок; на момент письма :3343 и :3345):
  `meta["lines"] = args.lines` — и **двумя строками ниже** `meta.update(json.loads(args.meta))`.
  Порядок и есть дефект: правая сторона `dict.update` побеждает.
- Парсер: `p.add_argument("-l", "--lines", help="Line range (stored in meta)")` и
  `p.add_argument("--meta", help="JSON metadata string")` — оба необязательные, оба
  свободного формата, взаимоисключения не объявлено.
- Живой писатель, ради которого это не гипотетика (замер держателя, корпус BT-7):
  `~/.claude/skills/arch-health/state/pending-2026-08-17-arch-health.py` — **шесть**
  вызовов, каждый передаёт И `-l "a-b"` (строка), И `--meta '{"lines": [a, b], …}'`
  (список). То есть в БОЕВОМ потоке `-l` не приземлялся НИ РАЗУ.
- Поверхность одна: `--lines` есть только у верба `add`. MCP-тула с этим аргументом
  нет — **golden не двигается** (проверь сам перед тем, как поверить).

## 2. Форма — рекомендация ★ с названной ценой; отклонение разрешено по КОДУ

Карта называет три направления. Мой разбор против правил репозитория:

- **(а) ★ ОТКАЗАТЬ на конфликте.** `-l` задан И распарсенный `--meta` несёт ключ `lines`
  со ЗНАЧЕНИЕМ, отличным от `-l` → `sys.exit(1)` с текстом, называющим ОБА написания и
  то, какое из них не приземлилось бы. Равные значения — не конфликт, проходят.
  Опора: CLAUDE.md, CB-28 — «пробрасывай, когда путь есть; отказывай только когда пути
  нет ни одного». Здесь оба написания метят в ОДИН ключ `meta.lines`: пути «уважить оба»
  не существует, значит отказ — единственный честный ответ.
  **Цена, названная вслух:** шесть вызовов arch-health начнут падать с exit 1, пока автор
  скрипта не уберёт одно из двух написаний. Это ПРАВИЛЬНЫЙ исход — его `-l` и так был
  мёртв, — но это ломающее изменение живого писателя, и оно обязано попасть в CHANGELOG
  строкой, которую автор скрипта поймёт холодной головой.
- **(б) применить `-l` ПОСЛЕ `--meta`** — отвергаю и говорю почему: это молча
  ПЕРЕВОРАЧИВАЕТ приземляемое значение у существующих вызовов (список → строка). Форма
  хранимого значения — вход грамматики захвата BT-7 (206 строк корпуса — `list[int]` по
  контракту libcheck); менять её незаметно ради починки «тихого отбрасывания» значит
  заменить один тихий сдвиг данных другим.
- **(в) только документировать прецеденцию в `help`** — не закрывает класс CB-15 вообще;
  годится ТОЛЬКО как довесок к (а), не как замена.

**Мандат:** если чтение кода покажет, что (а) невозможна или вредна (например, обнаружится
второй живой писатель, для которого равенство значений недостижимо) — **СТОП и доклад
мне через возврат (3)→(2)**, с тем, что именно в коде опровергает предписание. Предписание
в брифе — тоже предпосылка. Смысл, который держим: **типизированный аргумент не может
быть отброшен успешно-выглядящим вызовом.** Буква (какой именно текст ошибки, где именно
стоит проверка) — твоя.

## 3. Обязательный свип популяции (докладывать, НЕ чинить)

Этот репозиторий раз за разом ловит себя на том, что «популяция больше списка». Свипай по
ФОРМЕ, не по имени: `grep -rn 'meta\.update(\|\.update(json\.loads' src/`.

Мой прогон нашёл ДВА близнеца — проверь их и **опиши в возврате, чиним ли**; правку в этот
юнит НЕ бери без моего слова:

- `findings.py` `update_finding`: `new_meta["notes"] = notes` … `new_meta.update(meta_update)`
  — `--meta-update` с ключом `notes` бьёт явный `notes=`/`append_note`. Отличие от CB-129:
  сайт сидит внутри блока с ЗАЯВЛЕННЫМ контрактом упорядочивания (наследие CB-16, коммент
  прямо над ним), то есть порядок там, возможно, намеренный — но прецеденция нигде не
  ОБЪЯВЛЕНА. Это «недеклар», а не обязательно «дефект».
- `reqs.py` `update_requirement`: та же пара строк, тот же вопрос.

Если решишь, что это настоящий success-shaped discard — **заведи карту(ы)**, не расширяй
юнит. Если решишь, что нет — скажи почему, одной фразой на сайт.

## 4. Тесты — обязательный минимум

- **Поведенческий тест CLI**, вызывающий `cli.main` в процессе (прецеденты: `tests/test_fsio.py`,
  `tests/test_findings.py`), а не только юнит-тест хелпера: дефект живёт в СКЛЕЙКЕ
  парсера и хендлера, и тест на хелпере его не увидит.
- Три случая минимум: конфликт (отказ), равные значения (проходит), только одно из двух
  написаний (проходит и приземляется — в ОБЕ стороны, иначе тест вакуозен).
- **Мутационная проба обязательна и делается во ВРЕМЕННОМ worktree**
  (`git worktree add <tmp> <sha>` → проба → `remove --force`), НИКОГДА в рабочем дереве:
  окно между мутацией и откатом в общем дереве однажды уже дало закоммиченного мутанта
  (инцидент Т-15). Мутант, который ОБЯЗАН упасть: возврат порядка двух строк.
- `_cmd_update`-порядок арм `json.JSONDecodeError` перед `ValueError` не трогать: если
  твоя проверка бросает `ValueError`, убедись, что она не проезжает по существующему
  контракту упорядочивания армов (`tests/test_findings.py::TestRetriageCliContract`).

## 7. Харнес — обязательная механика

- `tools/worktree-setup.sh fix/cb-129-lines-meta-conflict` — из КОРНЯ репо. Клейм берёт он.
- Работа — **только внутри** `.worktrees/fix-cb-129-lines-meta-conflict`. Проверяй, в каком
  чекауте ты, перед КАЖДОЙ правкой файла.
- Тесты и линт — **в worktree** и **с `--extra dev`**:
  `uv run --extra dev python -m pytest tests/ -q`, `uv run --extra dev ruff check src/ tests/`.
  Без `--extra dev` свежий worktree умирает на `No module named pytest`. Никогда не
  валидируй ветку прогоном из main — `pythonpath=["src"]` резолвится от того чекаута, в
  котором запущен.
- Ruff — **0.15.7** (0.16.x красит весь репозиторий). `ruff format` НЕ гейт.
- Интеграция — `tools/worktree-finish.sh fix-cb-129-lines-meta-conflict --merge-msg '…'`,
  **из корня репо**.
- **ЗАПРЕЩЕНО** тебе и любому твоему субагенту: `uv run --python …`, `uv sync`, любая
  пересборка `.venv`. Эксперименты — под `/tmp`.
- **Не трогай `tools/` и харнес** — территория DIR-1.
- **Если `worktree-finish.sh` откажет на грязном main** (`_guard_main_clean`, чужой
  staged-WIP параллельной сессии — семья Э-к, пять рецидивов): **НЕ стэшить чужое** (окно
  гонки, инцидент Т-5), **НЕ ждать пробуждения**. Делай **polling**: цикл
  `git status --porcelain` раз в ~60 с, до снятия блокировки, и повторяй finish тем же
  `--merge-msg`. Доложи держателю фактом (время начала блокировки и что именно застейджено),
  но работу не бросай.
