## 2. Что сделать

1. Параметр `view` у MCP `query` и `recent`, умолчание **`"full"`** (решение куратора: `"summary"` по
   умолчанию молча отнял бы `meta` у текущих читателей — класс CB-15; смена умолчания — отдельным
   решением по недельному замеру, раздел 5 задания).
2. **Неизвестное значение — отказ словами пакета**, через `ValueError` в теле с перечнем допустимых
   значений (тогда `server._RefusalsReachTheClient` донесёт текст клиенту). Не полагайся на то, что
   откажет библиотека типов: её текст чужой (см. CB-326). Если схему удаётся снабдить перечнем
   `enum` ТАК, чтобы отказ по неизвестному значению всё равно давали слова пакета, — сделай; если это
   значит отдать отказ библиотеке — не делай, и запиши почему. Неверный ТИП (`view=1`) пусть
   остаётся за библиотекой — это правило CB-326, не меняй его.
3. Строка вида `"summary"` — ровно раздел 3 задания: `id`, `severity`, `category`, `file`, `status`;
   `description`, обрезанное до 200 ЗНАКОВ (срез строки Python, без многоточия); флаг
   `description_truncated`; `blocker_count` — только если строка из ветки `deferred`; `loc` — только
   при `resolve_anchors=True` у `query`, значение той же функцией, что даёт `_anchor_cell`; поля
   `meta` нет, остальных полей тоже нет (закрытая форма).
4. Ключи самой выдачи сохраняются в обоих видах (`grouped`, `total`, `limit`, `offset`; у `recent` —
   `total`, `limit`, `offset`, `since`, `status`). Ответ с `group_by` вид НЕ меняет (строк там нет).
   Вид применяется на ОБОИХ выходах ветки `deferred`: раннем пустом (там строк нет, но проверь, что
   форма ответа та же) и обычном.
5. Проекцию делай ОДНОЙ функцией уровня модуля, которую зовут обе обёртки. `_anchor_cell` подними на
   уровень модуля (одна копия; командная строка зовёт её же). Перемещение внутри одного файла —
   допустимо вручную, но после коммита покажи `git blame -w -M` на перенесённых строках: авторство
   должно остаться за исходными коммитами.
6. Описания обоих инструментов: `view` — `"summary"` назван видом для просмотра списков, `get` —
   способом получить полную карточку; умолчание `"full"` и почему — одной фразой.
7. Пересобери снимок схем осознанно; в отчёте — дифф снимка (только `query`/`recent` должны
   измениться).
8. `CHANGELOG.md`, раздел `[Unreleased]` — одна запись для пользователя.

## 3. Критерий приёмки — каждое свойство закреплено тестом И доказано пробой порчей

Тесты — через настоящую границу MCP (как делают соседние тесты инструментов — найди образец), а не
только через функцию проекции. Для каждого свойства: сломай ИМЕННО его в коде → покажи, что краснеет
ИМЕННО этот тест → верни. Запиши таблицу «порча → упавший тест» с выводом прогона.

1. в `"summary"` нет `meta` (и вообще нет полей вне закрытого набора);
2. описание > 200 знаков обрезано до 200 знаков и `description_truncated: true`; короткое не тронуто,
   `false`; граница 200 ровно — `false`; описание кириллицей — считаются знаки, не байты (порча:
   обрезка по байтам `encode()[:200]` обязана ронять тест);
3. ключи выдачи на месте в обоих видах, у обоих инструментов;
4. `deferred`: (а) обычный путь — `blocker_count` есть в `"summary"`; (б) ранний пустой возврат —
   форма ответа при `view="summary"` совпадает с формой при `"full"`; порча — отдельно на каждом пути;
5. неизвестное `view` → отказ, текст называет допустимые значения; и у `query`, и у `recent`; также
   на пути `status="deferred"` с пустым результатом (отказ не должен зависеть от содержимого трекера —
   урок CB-196);
6. `"full"` совпадает с сегодняшней выдачей ПОЛЕ В ПОЛЕ. Два доказательства: тест, сравнивающий
   `view="full"` и вызов без `view` с результатом доменной функции (`query_findings` /
   `recent_findings`) плюс `blocker_count` — не с константой; и одноразовый дифференциальный прогон:
   один и тот же скрипт на `main` (до правки) и на ветке над ОДНОЙ копией базы, дифф JSON пуст —
   вывод в отчёт;
7. `recent` ведёт себя как `query` (свойства 1–3, 5 у `recent`);
8. `loc` при `resolve_anchors=True` — значение `_anchor_cell`, без него ключа `loc` нет.
