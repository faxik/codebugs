# BT-4 — Контракт свежести остальных колонок дедуплицированной карты

Большая задача направления DIR-2 (Identity находок). Заведена 2026-08-20 держателем DIR-2.
**Статус процесса: черновик — до обязательного adversarial-review-x2 (§8.3б) и ратификации
владельцем. Юниты вниз не уходят до ратификации (§7 п.4).**
По §13: BT = **одно нерешённое проектное решение** + карты-симптомы.

## Нерешённое решение (одно)

Что делает дедуп-бамп с каждой из трёх колонок наблюдения, которые сегодня молча
отбрасываются: **`tags`, `source`, `reported_at_ref`**. Каждое наблюдение их поставляет,
ring их записывает, строка их не видит.

## Карты-симптомы

CB-103 (population card, `needs-decision`) — единственная; она сама итог sibling-sweep
CB-52-дерева и намеренно one-card-over-population (урок CB-24→CB-27→CB-36).

## Контекст уже решённого (неизменяемые факты, не пересматриваются здесь)

- `severity` — эскалация-только на бампе, ратифицировано (CB-52, приземлено).
- `reported_at_commit` — колонка заморожена (first-report provenance), читатели
  консультируют ring; ратифицировано CB-53/CB-63, приземлено мерджем `fc4f126` (Т-5).
- `file`, `description` — заморожены НАМЕРЕННО: fingerprint-входы; переписывание = re-key
  identity, отдельный переговорный контракт (CB-43). Названы, чтобы не перелитигировать.

## Свежие предпосылки (добыты DIR-2 2026-08-20 против приземлённого кода, после Т-3/Т-5)

- `findings.py:490-501` — ring-запись несёт `at, severity, file, description, source,
  tags, reported_at_commit, reported_at_ref` (+`meta`).
- `findings.py:576-577` — SET-клауза бампа: `occurrence_count`, `last_seen_at`,
  `updated_at`; + `status` (reopen), + `severity` (эскалация CB-52). `source`/`tags`/
  `reported_at_ref` не пишутся.
- `query(tag=)` читает **колонку** `tags`, не ring (утверждение CB-103; при x2 —
  перепроверить file:line фильтра).
- Бамп срабатывает и на fingerprint-hit из `import_findings` (live-hit бампает, CB-51),
  поэтому у любого «бамп обновляет X» есть импортный угол: import — не наблюдение.

## Связанное, здесь НЕ решаемое

Мета-находка CB-103: CB-63 объявил тотальность над «контрактом свежести» и перечислил 2
колонки из 5 — предикаты популяций нуждаются в гейте, не в списке (evidence для CB-37,
направление DIR-1/BT-1-соседство). Передать куратору как связь направлений, не решать в BT-4.

## Процесс

1. adversarial-review-x2 этого документа (обязателен, §8.3б) — вход: этот файл + CB-103 +
   предпосылки против кода.
2. Ратификация владельцем per-column таблицы (батч-канал стратсессии; срочности нет).
3. После ратификации — нарезка юнитов (3): ожидаемо один юнит на `tags` (запись + tests +
   MCP/CLI без изменения сигнатур), докстроки для `source`/`reported_at_ref` — попутный
   груз того же юнита.
