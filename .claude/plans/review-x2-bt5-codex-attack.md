## major_risks

- Category signal has a hard T-10 dependency under the ratified frame | [`findings.py:470`](/home/faxik/w/codebugs/src/codebugs/findings.py:470), [`findings.py:675`](/home/faxik/w/codebugs/src/codebugs/findings.py:675), [`findings.py:690`](/home/faxik/w/codebugs/src/codebugs/findings.py:690) | Today `_occurrence_entry` does not record category, and live/reopen paths return immediately after `_bump_row`; the observed category is therefore not persisted. Building the signal from transient input would contradict “already-recorded facts.” T-10 must land first for live/reopen category divergence; the sketch’s “no hard dependency” claim is false.

- Severity `from` is lost before the response seam | [`findings.py:585`](/home/faxik/w/codebugs/src/codebugs/findings.py:585), [`findings.py:594`](/home/faxik/w/codebugs/src/codebugs/findings.py:594), [`findings.py:808`](/home/faxik/w/codebugs/src/codebugs/findings.py:808) | `_bump_row` computes `escalated` while holding the old row, but returns only the mutated `RETURNING *` row. `_finalize_add` cannot reconstruct the pre-escalation severity, especially on the first bump. The proposed `{from,to}` shape requires a new internal outcome channel, not mere response decoration.

- The stated action vocabulary is incomplete | [`findings.py:714`](/home/faxik/w/codebugs/src/codebugs/findings.py:714), [`findings.py:717`](/home/faxik/w/codebugs/src/codebugs/findings.py:717), [`test_dedup.py:284`](/home/faxik/w/codebugs/tests/test_dedup.py:284) | The exact vocabulary is `created|bumped|reopened|recurrence_of_closed`. A dismissed twin returns `was_new: true`, not a match-shaped `was_new: false`. Omitting this fourth state corrupts the proposed closed contract and likely causes clients gated on `was_new == false` to miss the very signal BT-5 targets.

- `prior_status` is available only transiently, not in the response outcome | [`findings.py:623`](/home/faxik/w/codebugs/src/codebugs/findings.py:623), [`findings.py:714`](/home/faxik/w/codebugs/src/codebugs/findings.py:714), [`findings.py:730`](/home/faxik/w/codebugs/src/codebugs/findings.py:730) | `_add_one` has `closed["status"]`, but persists only `meta.recurrence_of` and returns the new row plus action. `_finalize_add` cannot emit `prior_status` without carrying it through a redesigned outcome or performing a new read.

- The “wire golden” does not guard response changes | [`tests/_mcp_schema.py:31`](/home/faxik/w/codebugs/tests/_mcp_schema.py:31), [`tests/_mcp_schema.py:53`](/home/faxik/w/codebugs/tests/_mcp_schema.py:53), [`test_boundary.py:145`](/home/faxik/w/codebugs/tests/test_boundary.py:145) | The golden captures only name, description, and `inputSchema`; it omits `outputSchema` and all result payloads. Adding `attention` alone produces no golden change. Only the necessary docstring edit would move it. Calling the golden a response compatibility gate is false assurance.

- Computing signals in `_finalize_add` can introduce a post-commit failure | [`findings.py:791`](/home/faxik/w/codebugs/src/codebugs/findings.py:791), [`findings.py:825`](/home/faxik/w/codebugs/src/codebugs/findings.py:825), [`test_dedup.py:582`](/home/faxik/w/codebugs/tests/test_dedup.py:582) | Finalization runs after commit and already has a dedicated corruption contract. Parsing the occurrence ring, normalizing legacy values, or validating signal records there could fail after the observation landed. Signal facts must be captured safely inside the transaction and finalization kept mechanical.

- “Closed vocabulary” is not enforced by the public type | [`findings.py:2058`](/home/faxik/w/codebugs/src/codebugs/findings.py:2058), [`findings.py:2117`](/home/faxik/w/codebugs/src/codebugs/findings.py:2117), [`func_metadata.py:396`](/home/faxik/w/codebugs/.venv/lib/python3.13/site-packages/mcp/server/mcpserver/utilities/func_metadata.py:396) | Both wrappers return `dict[str, Any]` shapes, yielding an arbitrary-property output schema. Misspelled signals, missing fields, duplicate signals, and extra keys remain wire-valid. The proposed closure currently exists only in prose.

## design_smells

- The response premise is only half-right | [`findings.py:825`](/home/faxik/w/codebugs/src/codebugs/findings.py:825), [`findings.py:837`](/home/faxik/w/codebugs/src/codebugs/findings.py:837), [`findings.py:2095`](/home/faxik/w/codebugs/src/codebugs/findings.py:2095) | `add` returns the entire converted database row plus two response-only keys; the MCP wrapper returns it unchanged. Calling this merely “row + was_new + dedup_action” is structurally accurate, but the abbreviated action set is not.

- “Absent is safer because CB-25” is unsupported and arguably inverted | [`findings.py:927`](/home/faxik/w/codebugs/src/codebugs/findings.py:927), [`server.py:107`](/home/faxik/w/codebugs/src/codebugs/server.py:107) | CB-25 concerns falsey input values disabling filters, not an output collection. An absent key forces existence checks and makes one response type state-dependent; `attention: []` supports unconditional iteration. Omission may reduce tokens or limit additive-key exposure, but that is a different argument.

- Supplied-versus-derived provenance must be captured before `_add_one` rewrites it | [`findings.py:675`](/home/faxik/w/codebugs/src/codebugs/findings.py:675), [`findings.py:676`](/home/faxik/w/codebugs/src/codebugs/findings.py:676), [`findings.py:1404`](/home/faxik/w/codebugs/src/codebugs/findings.py:1404) | After fallback derivation, `fingerprint` is non-null in both cases. Import also hands `_add_one` a pre-resolved derived fingerprint. A naive `fingerprint is not None` test will misclassify provenance; snapshot a boolean at the observation entry point.

- “After normalization” is underspecified for legacy stored categories | [`findings.py:325`](/home/faxik/w/codebugs/src/codebugs/findings.py:325), [`findings.py:340`](/home/faxik/w/codebugs/src/codebugs/findings.py:340), [`types.py:190`](/home/faxik/w/codebugs/src/codebugs/types.py:190) | Stored rows may retain pre-CB-60 spellings, and SQLite can contain non-string categories. Comparing normalized observed text to raw stored text creates spelling-only false positives; normalizing a non-string stored value raises. The sketch needs an explicit comparison and malformed-legacy policy.

- A third attention opt-out flag would be gratuitous proliferation | [`findings.py:1128`](/home/faxik/w/codebugs/src/codebugs/findings.py:1128), [`findings.py:1153`](/home/faxik/w/codebugs/src/codebugs/findings.py:1153), [`findings.py:1158`](/home/faxik/w/codebugs/src/codebugs/findings.py:1158) | Import ignores the per-row objects and returns only `ImportReport` counts. It never calls `_finalize_add`, so attention naturally has no return channel. Even after T-9 adds `promote_tags=False`, no `emit_attention=False` flag is needed.

- The three minimal record shapes are not themselves overengineered | [`findings.py:505`](/home/faxik/w/codebugs/src/codebugs/findings.py:505), [`findings.py:60`](/home/faxik/w/codebugs/src/codebugs/findings.py:60) | Each signal carries genuinely different evidence. A common nested `details` envelope would add indirection without improving semantics. The overengineering threat is flags and parallel recomputation, not the discriminated records.

- Reopen exclusion is mechanically valid but weakly justified | [`findings.py:700`](/home/faxik/w/codebugs/src/codebugs/findings.py:700), [`findings.py:838`](/home/faxik/w/codebugs/src/codebugs/findings.py:838), [`func_metadata.py:571`](/home/faxik/w/codebugs/.venv/lib/python3.13/site-packages/mcp/server/mcpserver/utilities/func_metadata.py:571) | `dedup_action:"reopened"` is serialized to MCP clients and is not stripped. However, “clients already have a field” is not by itself persuasive when BT-5’s motivation is that clients ignore existing fields. The exclusion stands only because the owner-fixed threshold excludes reopen.

- Batch supports per-row extension, but its MCP presentation has two forms | [`findings.py:1463`](/home/faxik/w/codebugs/src/codebugs/findings.py:1463), [`findings.py:1486`](/home/faxik/w/codebugs/src/codebugs/findings.py:1486), [`func_metadata.py:563`](/home/faxik/w/codebugs/.venv/lib/python3.13/site-packages/mcp/server/mcpserver/utilities/func_metadata.py:563) | Domain results are one dict per input and can carry per-row attention. MCP unstructured content flattens the list into one content block per result, while structured output wraps the list. Documentation and wire tests must cover both client consumption modes.

- Strict-arguments middleware has no response-key interaction | [`server.py:125`](/home/faxik/w/codebugs/src/codebugs/server.py:125), [`server.py:148`](/home/faxik/w/codebugs/src/codebugs/server.py:148) | It examines only `tools/call` argument names before dispatch. No middleware or argument-schema change is required for `attention`.
