## Замысел

CB-60 защищает только НОВЫЕ строки. Существующий корпус хранит вариантные написания
категорий, а `fingerprint` **хранится**, не пересчитывается, и категория — вход дериватного
хеша. Отсюда CB-113(a): до-гейтовая строка, ре-наблюдённая СВОИМ ЖЕ написанием, форкает
identity (наблюдение нормализуется до хеширования, хранимый хеш держит старое написание;
гейт не отказывает, потому что `_existing_categories` нормализует хранимые написания для
теста членства). Ретро-fold сворачивает корпус к канону, ре-деривирует хранимые `auto:v1`
хеши и тем закрывает форк.

## Задание

### 1. Доменная функция `normalize_categories`

В `findings.py`, рядом с `get_categories`:

```python
def normalize_categories(
    conn, *, fold_map: dict[str, str] | None = None, apply: bool = False
) -> dict[str, Any]:
```

**Дефолт `fold_map=None`** — механический fold: для каждого хранимого написания цель =
`normalize_category(написание)`. Это ровно те три механических пары, к которым кросс-модельный
ревью CB-61 велел сузить первую миграцию; семантические семейства из референсного census — НЕ
реализовывать и не подмешивать.

**Валидация переданной `fold_map`** (до всего): ключи и значения — строки; значение обязано
быть каноническим (`normalize_category(v) == v`), иначе `ValueError` с указанием пары — иначе
fold породил бы написание, которое следующее же наблюдение свернёт снова. `{}` — легальный
явный no-op (отчёт с нулями), не ошибка; `None` — дефолт. Это разные вещи (доктрина
«no filter — `None` и `""`, не truthiness»).

**Популяция**: все строки `findings` (терминальные включительно, вердикт 5), у которых
`category` — строка и цель fold отличается от хранимого написания. Не-строковая `category`
(легаси explicit-id строка) — пропуск + счётчик, не исключение (та же логика, что в
`_existing_categories`).

**Политика по fingerprint для каждой переименовываемой строки:**

| Хранимый fingerprint | Действие |
|---|---|
| `NULL` | только переписать `category`; хеш не трогать |
| не `auto:v1:` (supplied) | только переписать `category`; хеш **не трогать** |
| `auto:v1:…` | **round-trip**, затем ре-деривация — см. ниже |

**Round-trip — обязателен, это ядро честности шага 3.** Для `auto:v1`-строки сначала
проверь, что хранимые входы вообще воспроизводят хранимый хеш:
`_derive_fingerprint(старая_category, file, description, json.loads(meta_json)) == fingerprint`.

- совпало → ре-деривация с новой категорией, те же `file`/`description`/`meta` (та же версия
  нормализатора, меняется ТОЛЬКО категорийный вход — дисциплина CB-54);
- не совпало (или `meta_json` не парсится) → строка **пропускается целиком**: ни категория,
  ни хеш не пишутся, строка попадает в `unverifiable` отчёта. Обоснование, зафиксируй его в
  докстринге: переписать категорию без ре-деривации — это и есть дефект, который карта
  закрывает (перманентный десинк identity), а сфабриковать хеш из входов, которые
  доказуемо не воспроизводят хранимый, — хуже. Не останавливает прогон (стоп ратифицирован
  только для коллизий), но `unverifiable > 0` печатается заметно, как решение для оператора.

**Коллизии (ратифицировано владельцем: report-and-stop, НЕ авто-мерж).** Посчитай
пост-fold мультимножество `(fingerprint, status)` по всем строкам с не-NULL хешем
(переименованные — с новым значением, остальные — с хранимым). Любой fingerprint, который
пост-fold держат **≥2 ЖИВЫЕ** строки (`LIVE_STATUSES`) — коллизия. Пре-существующих дублей
среди живых быть не может (частичный индекс), значит любая найденная коллизия порождена
fold-ом. При хотя бы одной коллизии: **не пишется НИЧЕГО** (весь прогон, не «эта пара»),
отчёт несёт `stopped: true` и **именованный** список пар (`fingerprint` + список id + их
категории «из/в»). Коллизионные пары — материал для В-3/CB-46, их надо назвать.

**Транзакция.** Весь `apply`-прогон — ОДИН `db.txn(conn)`: чтение популяции под write-lock
(CB-24), решение о коллизиях, затем UPDATE'ы. Никакого `conn.commit()` внутри. Стоп =
ничего не легло. Dry-run (`apply=False`) **не открывает write-транзакцию вообще** и не пишет
ни байта.

**Ring НЕ переписывается** — `meta` не участвует в UPDATE ни одним байтом. Occurrence-записи —
вербатим-улики истории.

**Ре-кей — санкционированная точка входа, и это надо объявить.** `update_finding` документирует
`fingerprint` как immutable и обязан таким остаться; эта миграция пишет хеш своим собственным
UPDATE и в докстринге прямо говорит: это единственный санкционированный ре-кей, релаксация
объявлена здесь, `update_finding` её не получает. Не звать `update_finding`.

UPDATE — без `RETURNING` (правило RETURNING), `rowcount != 1` на строку → исключение (весь
прогон откатывается).

**Форма отчёта** (`dict[str, Any]`, одинаковая в dry-run и apply):
`applied`, `stopped`, `fold_map` (только реально работающие пары), `rows_scanned`,
`renames` (список `{id, from, to, fingerprint_action, old_fingerprint, new_fingerprint}`),
`counts` (`category_only`, `refingerprinted`, `supplied_untouched`, `null_untouched`,
`unverifiable`, `skipped_non_string`), `collisions`, `unverifiable`.

## Критерии приёмки (TDD — красный тест раньше фикса)

1. **CB-113(a) закрыт.** Фикстура симулирует до-гейтовую строку прямым INSERT'ом:
   `category="Process Improvement"`, `fingerprint=_derive_fingerprint("Process Improvement",
   file, desc, meta)`. **До fold**: `add_finding` с тем же написанием/файлом/описанием
   создаёт НОВУЮ строку (форк) — assert. **После** `normalize_categories(apply=True)`:
   категория `process_improvement`, хеш = `_derive_fingerprint("process_improvement", …)`;
   то же наблюдение **бампает** исходную строку (`was_new` False, `occurrence_count` 2).
2. **Dry-run не пишет ни байта**: снимок `SELECT id, category, fingerprint, meta_json FROM
   findings` (плюс хеш файла БД для file-based теста) до и после — идентичны.
3. **Коллизия → стоп и нулевая запись**: искусственная пара — две ЖИВЫЕ строки, чьи
   `auto:v1` хеши расходятся только категорией-вариантом и которые после fold сходятся в один
   хеш. `apply=True` → `stopped: true`, пара **названа** в отчёте, БД не изменилась ни в одной
   строке (включая те, что свернулись бы успешно). CLI `--apply` в этом случае — exit 1.
4. **supplied/NULL нетронуты**: строка с supplied fingerprint и строка с `fingerprint IS NULL`
   получают новую категорию, хеш — байт в байт прежний; счётчики отчёта это отражают.
5. **Round-trip/unverifiable**: строка с `auto:v1`-хешем, который не воспроизводится из
   хранимых входов (подставить `auto:v1:` + произвольные 32 hex) — пропускается ЦЕЛИКОМ
   (категория тоже не меняется), попадает в `unverifiable`, прогон продолжается.
6. **Ring не тронут**: после `apply=True` `meta.occurrences` переименованных строк идентичны
   до-fold значению.
7. **Терминальные строки сворачиваются** (вердикт 5): `fixed`-строка с вариантным написанием
   после fold несёт канон — иначе `_existing_categories` продолжит легитимизировать вариант.
8. **Валидация fold_map**: неканоническая цель → `ValueError` с указанием пары; `{}` — no-op
   с нулями; не-строковые ключ/значение → `ValueError`.
9. Вся сюита зелёная **ИЗ worktree**: `uv run --extra dev python -m pytest tests/ -q`;
   `uv run --extra dev ruff check src/ tests/` (ruff 0.15.7) чист; wire golden совпадает.
