## Тройка П-Б

**Замысел.** Наблюдение, принёсшее новый тег, видно тегово-фильтрующим читателям
(`query(tag=)`, `tag_report`), а не только рингу. Импорт — не наблюдение и не протекает.
Минимальная форма, ничего сверх ратифицированного.

**Задание (ратифицировано, минимальная форма C-ALT-1):**
1. `_bump_row` выполняет union-merge тегов наблюдения в колонку: merged-множество
   считается ОДИН раз из залоченной сырой строки; **strict-parse** хранимых тегов
   (`json.loads` pre-write — класс malformed-stored-tags переезжает с post-commit
   `PostCommitCorruptionError` на чистый pre-write отказ; закреплявший старую
   классификацию тест меняется ОСОЗНАННО и это фиксируется в его докстринге);
   точное строковое равенство (НИКАКОГО casefold), первый-встреченный порядок,
   дедупликация, сериализация контейнера один раз (CB-82), ровно один `tags = ?`
   ВНУТРИ билдера `sets` со своим параметром (CB-16; докстринг `_bump_row` :545-556 —
   правило парности фрагмент+параметр), `meta = ?` остаётся один, `RETURNING *` + fetch
   (правило RETURNING).
2. Ветки дедупа (тотальность CB-43): live-бамп — union; **reopen — union** (регрессия —
   наблюдение, `fixed-in-1.2` доезжает); recurrence — новая строка, теги наблюдения
   естественно; ручной `update_finding(status=...)` — НЕ наблюдение, union не делает
   (он и не проходит через `_bump_row` — пинуй тестом, что путь не приобрёл union).
3. **Импорт не протекает**: внутренний параметр `promote_tags` (имя финализируй по коду),
   `False` ровно на одном call site — `import_findings`; свой AST-ратчет по образцу
   `tests/test_dedup.py::TestEscalateOptOutRatchet` (ровно один опт-аут call site) + тест
   отсутствия параметра на публичной поверхности `add`/`batch_add`. `escalate` НЕ
   перегружать.
4. **МЕХАНИЗМА СНЯТИЯ НЕТ — суб-решение ОТКРЫТО владельцем, НЕ решать в юните.**
   Посадка идёт как сегодня: `update(tags=)` — полный replace, снятый тег может вернуться
   следующим наблюдением. Этот факт и открытость суб-решения (кэп / tombstones /
   `finding_tags`) — именованной строкой в CHANGELOG-записи и CLAUDE.md-тексте.
5. Обязательства посадки: расширение `tests/test_dedup.py::TestBumpSqlComposition`
   (шаблонный SQL: один `tags = ?`); CHANGELOG-запись (прецедент CB-52 — включая «импорт
   не протекает» и «снятие тегов пока полный replace, суб-решение открыто»); текст
   контракта в CLAUDE.md-секцию дедупа; wire golden из worktree (`PYTHONPATH=src uv run
   python tests/dump_schema.py > tests/golden/mcp_schema.json`), если описания
   инструментов изменились.
6. **Смежность НЕ трогать**: `if tag:`-truthiness фильтра (`findings.py:1865`) —
   территория CB-29, сериализовать, не чинить попутно.

**Критерий приёмки:** карта, ре-наблюдённая с новым тегом, находится `query(tag=)` по
нему (тест, падающий на откате union); импортный live-hit НЕ приносит чужих тегов (тест);
reopen-бамп несёт union (тест); ручной update пути не приобрёл (тест или структурный
довод); AST-ратчет и surface-absence тесты зелёные и падают на нарушении; сериализация
один раз (мутирующий контейнер — паттерн CB-82-теста); существующая сюита зелёная;
CHANGELOG/CLAUDE.md/golden — на месте.
