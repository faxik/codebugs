## §1. Замысел, и предпосылка задания ПОПРАВЛЕНА моим замером

Заказ владельца: человек или агент, впервые открывший `README.md`, за минуту понимает, что это **не
ещё один трекер задач**, а трекер **с идентичностью находок** — тот, где подача одного дефекта
дважды не создаёт две карточки, где место в коде переживает редактирование файла, где параллельные
агенты не наступают друг другу на ноги.

**Задание-гипотеза говорило, что README «нигде не говорит, чем инструмент отличается». Это неточно, и
неточность важна для формы.** Раздел `## Why codebugs` в README **есть** (строка 15) и написан
неплохо. Но он называет четыре проблемы — находки теряются, требования расходятся с кодом,
параллельные агенты гонятся, релизы теряют состав, — и **ни одна из них не является тем, что владелец
просит показать**. То есть README описывает codebugs как *долговременную память*, а не как трекер *с
идентичностью находок*. Задача не «добавить раздел, которого нет», а **сменить то, о чём говорит уже
существующий раздел**.

**И вторая половина замысла, которая делает работу дешёвой и безопасной: искомый текст УЖЕ НАПИСАН.**
Константа `INSTRUCTIONS` в `src/codebugs/server.py` (строка 580) — тот текст, который получает каждый
подключающийся клиент, — говорит почти в точности то, что просит владелец: дедупликация это замысел, а
не побочный эффект; повторная подача бумпает или переоткрывает карточку; место в коде якорится при
подаче и переживает правки; работаешь рядом с другими агентами — бери клейм; требования это отдельная
авторская сущность без дедупликации. **README — единственная из четырёх поверхностей, которая этого
не несёт.** Значит юнит приводит README к тому, что код уже говорит, а не сочиняет заново.

**Чего юнит НЕ делает.** Не переписывает README с нуля и не переводит его — язык английский, как
сейчас. Не изобретает механизм ради механизма (см. §3 про гейт). Не трогает `INSTRUCTIONS`, кроме
случая из §3, часть 4.

## §2а. ДОПОЛНЕНИЕ разведки, приземлённое ПОСЛЕ первой редакции брифа — включая поправку ко мне

Разведочный проход (отдельный агент, полный прогон примеров во временном трекере) принёс три вещи,
которых у меня не было, и одну поправку к моему собственному числу. **Всё это данные, а не факты:
перепроверь, как и мои.**

**(1) ПОПРАВКА КО МНЕ: числа модулей ДВА, и оба верны про разное.** Я написал «14». Это верно про
разрешённый список `--mode` у CLI. Самостоятельно регистрирующихся доменных модулей, отдающих
инструменты MCP, — **13**: у телеметрии `usage` есть команда CLI и нет инструмента MCP, поэтому

сами расходятся между собой**, и это пятое расхождение поверхностей, а не оговорка. Следствие для
части 2 §3: в тексте бары́шничать числом нельзя тем более; **гейт сравнивай с тем списком, который
ближе к таблице README, и назови в докстринге, какой из двух ты взял и почему.**

**(2) САМЫЙ ПЕРВЫЙ КОМАНДНЫЙ ПРИМЕР README НЕ РАБОТАЕТ НА НОВОМ ТРЕКЕРЕ.** Строка 183, `codebugs add
-s high -c n_plus_one …`, на свежесозданном трекере отказывает: категории в нём ещё нет, и нужен флаг
`--new-category`, о котором README не говорит ни слова. **Это худший из найденных дефектов по цене:

опечатки в названии категории) и подробно описан в `CLAUDE.md`; README о нём молчит.

**(3) ЛОЖНОЕ УТВЕРЖДЕНИЕ О ЗАВИСИМОСТИ, И ОНО ЛОМАЕТ УСТАНОВКУ.** README (строка 507) обещает
«no external runtime dependencies beyond `mcp>=1.0.0`». В `pyproject.toml` стоит `mcp>=2.0.0,<3` с
комментарием о том, что `server.py` использует класс из SDK версии 2, заменивший класс версии 1. То

**(4) Ещё три ложные ячейки в таблице режимов** (число инструментов на модуль): findings фактически

**(6) Механическая причина всего разом, и её стоит знать.** Гребёнка по `CHANGELOG.md` (1852 строки)

Это не повод переписывать его с нуля (объём остаётся прежним), но это объясняет, почему расхождение
не точечное, и **это же довод в пользу гейта**: без механизма README отстанет снова.

**(7) Что разведка ПОДТВЕРДИЛА без расхождений** — чтобы ты не тратил на это время повторно: весь
блок требований (импорт, сводка, проверка, запрос, обновление, экспорт), весь блок обходов, четыре

закрыть даже принудительно», автоматическое снятие блокировки при исправлении находки и — единственное

Проверь выборочно, но не переделывай целиком.

## §3. Форма выбрана уровнем (2) — четыре части

**Часть 1: вводный раздел говорит про уникальность, а не про память.** Перепиши `## Why codebugs`
(или поставь раздел перед ним — решай сам) так, чтобы он нёс: **идентичность находок** (подача
дважды не создаёт две карточки — бумпает или переоткрывает), **повторное открытие регрессии**,
**якоря места** (карточка переживает редактирование файла), **клеймы** для параллельных агентов,
**связи и группировку**, **счётчик наблюдений**, и **честные границы** — инструмент не отвечает кодом
0 там, где не смог посмотреть. Последний пункт — не украшение: это то, чем направление занимается
несколько смен подряд, и он отличает этот трекер сильнее прочего. **Бери формулировки из
`INSTRUCTIONS`**, а не выдумывай синонимы: две поверхности, говорящие одно разными словами, — это
следующее расхождение.

**Часть 2: счета из прозы УБИРАЮТСЯ, а не исправляются.** Не пиши «83 MCP tools» вместо «66» — этот
репозиторий трижды был неправ именно там, где в прозе стоял счёт, и `CLAUDE.md` говорит это о себе
прямым текстом. Скажи качественно («модули самозарегистрированы; полный каталог инструментов отдаёт
сам сервер») или сошлись на источник. **Таблица модулей при этом обязана стать полной** — это не
счёт, а множество, и его можно гейтить (часть 4).

**Часть 3: каждое фактическое утверждение проверено ПРОГОНОМ.** Это главный пункт приёмки, и
предъявляется он **списком: утверждение — команда — её фактический вывод — вердикт**. Утверждение, не
выдержавшее прогона, либо исправляется, либо удаляется; **ни одно не остаётся шире кода**. Все
командные примеры исполняются как написаны. Объём этой части отдай дешёвым субагентам.

**Часть 4: ГЕЙТ, дешёвый, и обещание у него УЗКОЕ.** Два утверждения, оба — сравнение множеств, а не
разбор прозы:
- множество модулей, названных таблицей README, **равно** разрешённому списку `--mode`;
- каждый верб, встречающийся в командных примерах README, **существует** в голдене поверхности
  `tests/golden/cli_surface.json`.

**И теперь самое важное в этом брифе.** Вчера на соседнем юните я предписал гейт с доводом
«перечисление не сходится, поэтому нужна проверка способности», и поставленный гейт **сам оказался
перечислением написаний**: он поймал одну обходную форму из тринадцати (карта CB-227). Поэтому здесь
я прошу обратного: **не расширяй обещание гейта.** Он НЕ проверяет, что README точен; он проверяет
два названных множества. **Напиши это в его докстринге теми же словами**, включая то, чего он не
видит (прозу, числа, поведение флагов, точность примеров). Гейт, чьё обещание шире проверяемого, —
основной класс вреда этого направления, и он уже дважды воспроизвёлся внутри собственных починок.

**Если гейт окажется дороже, чем выглядит, — не строй его, а назови цену в отчёте.** Владелец
написал это условием дословно: «не изобретай механизм ради механизма». Отказ с названной причиной
здесь законный исход, а не провал.

**И одно попутное решение, если увидишь.** Если «Typical Workflows» расходится с `INSTRUCTIONS` —
приведи к одному источнику. Дешевле, чем две правды. Правь README под сервер, а не наоборот: текст
сервера прошёл собственную приёмку и ратифицирован как контракт.

## §4. Канон К-18 — предпосылка самой правки

Правка-документация приходит с готовым оправданием («я же просто описал, как есть») и потому
проверяется хуже кода. Здесь предпосылок две, и обе твои.

**(а) Что новый вводный текст ПРАВДИВ.** Каждое обещание уникальности проверь исполнением: подай одну
находку дважды и покажи, что карточка одна; закрой и подай снова — покажи переоткрытие; отредактируй
файл и покажи, что якорь разрешается. **Если хоть одно из заявленных свойств не воспроизведётся —
это эскалация, а не повод смягчить формулировку.** Мерь во ВРЕМЕННОМ трекере, никогда в настоящем.

**(б) Что «уже написано в `INSTRUCTIONS`» действительно так.** Я цитирую этот текст как основание
формы. Прочти его целиком сам и скажи, если он обещает то, чего код не делает: тогда чинить надо
обе поверхности, и это данные для меня.

## §5. Оракул

**Главный пункт, и он от владельца дословно: приёмщику предъявляется список утверждений с командой
и её выводом.** Список — часть артефакта на ветке, а не сообщения.

**Обязано КРАСНЕТЬ после юнита (покажи оба состояния):**

1. Мутант, убирающий строку модуля из таблицы README, — гейт обязан покраснеть.
2. Мутант, добавляющий в README командный пример с несуществующим вербом, — гейт обязан покраснеть.
3. Мутант, добавляющий новый модуль в разрешённый список `--mode` без строки в README, — гейт обязан
   покраснеть. **Это половина, ради которой гейт и нужен:** первые две ловят порчу README, третья —
   рост продукта мимо README.

**Обязано ПРОХОДИТЬ:** полный набор без правок в чужих тестах; голдены не двигаются (юнит не меняет
поверхность, он её описывает — **если голден сдвинулся, ты сделал не то**).

**Строка «то же состояние, полученное ДРУГИМ способом»:** README может разойтись с продуктом не только
через новый модуль — через переименованный верб, удалённый флаг, изменившийся формат вывода, новый
инструмент MCP. Назови, сколько способов нашёл и сколько из них гейт видит. **Ожидаемый честный ответ
— «меньшинство»**, и так и напиши.

**Мутации — только в отдельном дереве** (К-5, К-15), `PYTHONDONTWRITEBYTECODE=1`, чистый
`__pycache__`, `grep -c` в подтверждение. **Ловушка:** проба, запущенная указанием пути к тестам без
смены рабочего каталога внутрь копии, молча измеряет главный чекаут.

Заполнено уровнем (3) по завершении Т-104. Каждый из семи поводов разобран поимённо; пустые
названы пустыми словами, а не пропущены. Полный список утверждений с командами и выводом лежит
отдельным артефактом на ветке — `.claude/plans/T104-README-claim-verification.md`.

### (б) `INSTRUCTIONS` обещает то, чего код не делает — ЭСКАЛАЦИЯ, решение за уровнем (2)

**Это единственная настоящая эскалация юнита, и она попала ровно в тот пункт, ради которого §4(б)
в брифе стоит.** Бриф цитирует константу `INSTRUCTIONS` (`src/codebugs/server.py:580`) как основание
формы: «искомый текст уже написан, README просто единственная из четырёх поверхностей, которая его
не несёт». Я прочёл текст целиком, как предписано, и в нём есть клауза шире кода:

> The code location is anchored automatically at file time (git-derived), so the card survives
> later edits

Утверждение безусловное. **Код так не делает.** Захват якоря отказывает, если само наблюдение не
назвало места в коде: `loc.py:566-568` требует непустого `parse_sites(meta)` и иначе выбрасывает
`_Refused("no_grammar")`. Ключи, которые считаются за «место», перечислены в `loc.py:314` —
`line`, `site`, `lines`, `sites`, `location`. Обычная подача вида `add -s high -c … -f файл.py -d
"…"` ни одного из них не несёт, и якоря не получает вовсе.

Насколько это не редкий угол — измерено не мной, а самим кодом, в комментарии на `loc.py:563-565`:
**63.6% строк трекера codebugs и 79.2% строк autosorter не называют места.** То есть для
большинства карточек «the card survives later edits» просто неверно.

Воспроизведено прогоном, обе стороны:

- карточка, поданная без span'а → `anchor-resolve` возвращает `"status": "unknown"`,
  `"reason": "no_grammar"`, `"line": null`;
- карточка, поданная с `--meta '{"lines":"5-7"}'`, после вставки 20 строк выше неё →
  `"status": "moved"`, `"line": 25`, `"end": 27`, `"survived": "3/3"`.

**Что я сделал и чего не сделал.** README написан по коду, а не по `INSTRUCTIONS`: там сказано
«When a report names a line range, the location is anchored at filing time from git», и отдельным
абзацем — что подача без span'а якоря не получает и что `anchor_resolve` в этом случае честно
отвечает `unknown` с причиной. `INSTRUCTIONS` я **не трогал**: бриф (§1 и §7(б)) оставляет решение
о второй поверхности за уровнем (2). **Сейчас две поверхности расходятся: README точен, сервер
обещает шире.** Чинить нужно `INSTRUCTIONS` — и, вероятно, не текстом, а вопросом, не должен ли
`add` предупреждать, когда наблюдение не назвало места; но это уже не мой уровень.

### (г) Расхождения, которые чинятся в КОДЕ, а не в README — названы, не чинены

Два, оба найдены при проверке утверждений, оба вне объёма юнита.

1. **Отказ гейта категорий называет пользователю CLI аргумент, которого в CLI нет.** Команда
   `codebugs add -c totally_new_thing …` отвечает: `… pass new_category=True to mint it
   deliberately`. `new_category=True` — написание аргумента MCP; в CLI флаг называется
   `--new-category`. Человек, набравший команду в терминале, получает совет передать то, чего у
   него нет. Цена реальная: это первая команда, которую набирает новичок (см. §2а(2) брифа), и
   сообщение об ошибке — единственное, что у него есть.

2. **Токен `all` в `--status` значит разное у разных вербов.** `codebugs query --status all` →
   `Invalid finding status: 'all'`, код 1. `codebugs anchor-resolve --status all` — законно, и
   собственная справка верба объясняет: «"all" widens to every status». Один и тот же токен в
   одноимённом флаге: у одного верба расширение, у другого ошибка ввода.

### (а) Предпосылка §4(а) — НЕ эскалация, но поправка к формулировке брифа

Все три заявленных свойства воспроизвелись, и сверх них ещё шесть (эскалация серьёзности в обе
стороны, «решение остаётся решением», клейм с отказом и автоснятие, сухой прогон отчёта о похожести,
`where` с каналом привязки) — Часть A артефакта.

Поправка касается третьего свойства. Бриф формулирует его безусловно: «якоря места (карточка
переживает редактирование файла)». **Оно верно только при условии, что подача назвала место в
коде**, и условие не маргинальное (числа выше, в пункте (б)). Я **не смягчал** формулировку в
README — смягчение было бы запрещено брифом; я назвал условие, а это другое действие. Оракул §4(а)
выполнен: свойство предъявлено исполнением, вместе с отрицательным случаем.

### (в) Цена гейта — НЕ эскалация, гейт построен

Оказался дешёвым: `tests/test_readme_surface.py`, три сравнения множеств, 0.07 с. Извлечение из
README структурное (таблица опознаётся по строке заголовка, примеры — по огороженным блокам), и на
неразобранной строке гейт падает, а не молчит. Четыре мутанта краснеют, каждый на своём утверждении;
база зелена до и после. Проба — в отдельном дереве, при `PYTHONDONTWRITEBYTECODE=1` и нуле каталогов
`__pycache__`.

**Обещание гейта не расширено, как и требовал бриф.** Он сравнивает три множества имён и **не**
проверяет, что README точен: слеп к прозе, к числам, к флагам и их поведению, к точности любого
показанного вывода, к тому, срабатывает ли команда, и к новым вербам и инструментам, которых README
не называет. Это записано теми же словами в его докстринге, включая перечень невидимого.

Одно отступление от буквы брифа, названное вслух: **третье утверждение добавлено сверх двух
заказанных** — имена инструментов из таблиц `| Tool | Purpose |` должны существовать в голдене MCP.
Механизм тот же, цена та же, и оно закрывает самую большую оставшуюся площадь README (шестьдесят с
лишним имён инструментов). Отступление сужает разрыв между обещанием и проверкой, а не расширяет
обещание, — но это отступление, и потому названо.

Второе, меньшее: гейт читает **живой** парсер (`tests.cli_surface.collect_cli_surface`), а не
голден `tests/golden/cli_surface.json`, который назван в брифе. Замысел брифа — «верб существует в
CLI»; живой парсер отвечает на это прямее и переиспользует собственный шов репозитория вместо
второго читателя.

**Какой из двух списков режимов взят:** CLI (шире, 14 модулей), а не `SERVER_NAMES` (13). README
описывает флаг, который принимают обе поверхности, а гейт по узкому списку позволил бы молча
выбросить `usage` из README. Названо в докстринге гейта.
